# pg-aje

A PostgreSQL extension for mapping relational data to JSON documents with ETAG-based optimistic concurrency control. It provides bidirectional read/write access to relational data through JSON document views, enabling document-style CRUD operations that automatically propagate to underlying tables.

Pure PL/pgSQL. No C compilation required.

[中文介绍](docs/introduction_v0.1.0_zh.md)

## Features

- **AJE Views** — Expose relational data as hierarchical JSON documents (single `data` JSONB column)
- **Full CRUD** — INSERT, UPDATE, DELETE on views automatically propagate to underlying tables
- **Composite PK** — Supports multi-column primary keys and composite foreign keys
- **Text PK** — Works with TEXT and other non-integer primary keys
- **JSONB Columns** — Native JSONB fields are preserved in documents
- **ETAG Concurrency** — MD5-based optimistic concurrency control prevents lost updates
- **Nested Arrays** — 1:N nesting via FK-based correlated subqueries, multiple nested arrays per view
- **Annotations** — Fine-grained control over which tables/columns are writable
- **Auto-Detect** — Automatically discover table columns when no field list is provided
- **Deep Merge** — `aje.jsonb_deep_merge()` for RFC 7396 JSON Merge Patch

## Requirements

- PostgreSQL 18+
- No additional extensions required

## Usage

### Create a View

```sql
-- With explicit field definitions
SELECT aje.create_view(
    'dept_dv',           -- view name
    'departments',        -- root table
    'public',             -- root schema
    'd',                  -- root alias
    '{"insert":true,"update":true,"delete":true}'::jsonb,  -- root annotations
    '[                    -- fields
        {"path": "dept_name", "column": "dept_name", "updatable": true},
        {"path": "location", "column": "location", "updatable": true},
        {"path": "staff", "type": "nested_array",
         "table": "employees", "alias": "e",
         "annotations": {"insert": true, "update": true, "delete": true},
         "link": {"fk_columns": ["dept_id"], "pk_columns": ["dept_id"]},
         "fields": [
            {"path": "emp_name", "column": "emp_name", "updatable": true},
            {"path": "job", "column": "job", "updatable": true}
         ]}
    ]'::jsonb
);

-- With auto-detect (all columns, all writable)
SELECT aje.create_view('simple_dv', 'my_table');
```

### Read Documents

```sql
-- Single-column JSONB result
SELECT jsonb_pretty(data) FROM dept_dv;

-- Extract fields
SELECT data->>'dept_name' FROM dept_dv WHERE (data->>'_id')::bigint = 1;
```

### Insert Documents

```sql
-- IDENTITY PK: _id auto-generated
INSERT INTO dept_dv (data) VALUES (
    '{"dept_name": "Research", "location": "Boston",
      "staff": [
        {"emp_name": "Alice", "job": "Engineer"}
      ]}'::jsonb
);

-- Non-IDENTITY PK: provide _id explicitly
INSERT INTO dept_dv (data) VALUES ('{"_id": "g1", "group_name": "Dev Team"}'::jsonb);

-- Composite PK: _id is a JSON object
INSERT INTO item_dv (data) VALUES (
    '{"_id": {"item_id": 1, "item_type": "PRODUCT"}, "title": "Widget"}'::jsonb
);
```

### Update Documents

```sql
-- Update root fields
UPDATE dept_dv SET data = jsonb_set(data, '{location}', '"New York"')
WHERE (data->>'_id')::bigint = 1;

-- Replace nested arrays (delete-and-reinsert strategy)
UPDATE dept_dv SET data = jsonb_set(data, '{staff}',
    '[{"emp_name": "Alice", "job": "Senior Engineer"}]'::jsonb
) WHERE (data->>'_id')::bigint = 1;

-- Update JSONB column
UPDATE item_dv SET data = jsonb_set(data, '{tags}', '{"color":"red"}'::jsonb)
WHERE (data->'_id'->>'item_id')::bigint = 1;
```

### Delete Documents

```sql
DELETE FROM dept_dv WHERE (data->>'_id')::bigint = 1;
```

### Manage Views

```sql
-- List views
SELECT * FROM aje.list_views();

-- Describe a view
SELECT jsonb_pretty(aje.describe_view('dept_dv'));

-- Validate a view
SELECT * FROM aje.validate_view('dept_dv');

-- Drop a view
SELECT aje.drop_view('dept_dv');
```

## Document Structure

Each AJE view produces documents with this shape:

```json
{
  "_id": 1,
  "dept_name": "Engineering",
  "location": "Building A",
  "_metadata": {
    "etag": "a1b2c3d4e5f6...",
    "xmin": 12345
  },
  "staff": [
    {"emp_name": "Alice", "job": "Engineer"},
    {"emp_name": "Bob", "job": "Manager"}
  ]
}
```

- **`_id`** — Primary key of the root table. For IDENTITY columns, auto-generated. For TEXT PK, a string. For composite PK, a JSON object like `{"item_id": 1, "item_type": "PRODUCT"}`
- **`_metadata.etag`** — MD5 hash for optimistic concurrency
- **`_metadata.xmin`** — PostgreSQL xmin for fallback concurrency

## Primary Key Handling

| PK Type | `_id` in Document | INSERT Behavior |
|---|---|---|
| `BIGINT GENERATED ALWAYS AS IDENTITY` | Integer, auto-assigned | Omit `_id`; auto-generated by database |
| `BIGINT NOT NULL` | Integer | Provide `_id` in document |
| `TEXT PRIMARY KEY` | String | Provide `_id` in document |
| Composite (multi-column) | JSON object | Provide `_id` as `{"col1": val1, "col2": val2}` |

For composite FKs in nested tables, all FK columns are automatically populated from the root `_id`.

## Annotation System

| Annotation | Default | Meaning |
|---|---|---|
| `insert` | `false` | Allow INSERT through the view |
| `update` | `false` | Allow UPDATE through the view |
| `delete` | `false` | Allow DELETE through the view |
| `check` | `true` | Include column values in ETAG |
| `noinsert` | — | Negation of `insert` |
| `noupdate` | — | Negation of `update` |
| `nodelete` | — | Negation of `delete` |
| `nocheck` | — | Exclude from ETAG calculation |

When a child table has `delete: false` (or `nodelete`), deleting the parent sets the child FK to NULL instead of cascade-deleting.

When a root table has `insert: false`, `update: false`, or `delete: false`, the corresponding operation raises an exception (`aje_insert_blocked`, `aje_update_blocked`, `aje_delete_blocked`).

## API Reference

| Function | Purpose |
|---|---|
| `aje.create_view(name, table, schema, alias, annotations, fields)` | Create an AJE view |
| `aje.drop_view(name)` | Drop an AJE view |
| `aje.list_views()` | List all registered views |
| `aje.describe_view(name)` | Get JSONB description of a view |
| `aje.validate_view(name)` | Validate view against actual schema |
| `aje.compute_etag(values)` | Compute MD5 ETAG from text array |
| `aje.jsonb_deep_merge(target, patch)` | Recursive deep JSON merge |
